# 연구생활장려금 관리 시스템 (Stipend Mentoring)

학생연구자의 학적 정보, 연구지원금 지급내역, 기관계정 정보를 통합 관리하는 웹 기반 관리 시스템입니다.

학적·지급·기관계정의 데이터 연동, 지급 현황 조회, 정합성 검사, 감사로그 관리, 역할별 접근 권한 관리 기능을 제공합니다.

## 1. 주요 기능

### 학생연구자 명부 관리
- 기준월별 학생연구자 명부 조회
- 학적상태 및 연구지원 자격 확인
- 지도교수별 담당 학생 조회
- 학생별 상세 정보 확인

### 연구지원금 지급 관리
- 기준월별 지급내역 조회
- 재원별 지급금액 및 지급 현황 확인
- 지급 계획과 실제 지급금액 비교
- 지급 부족 학생 및 부족금액 확인

### 데이터 연동
- JOB-ACAD: 학적 데이터 연동
- JOB-PAY: 지급 데이터 연동
- JOB-ACCT: 기관계정 데이터 연동
- 수동 연동 및 예약 연동 API 지원
- Mock 원천 데이터를 활용한 연동 테스트

### 데이터 정합성 및 이력 관리
- CHK-01~CHK-08 정합성 검사
- 데이터 변경 감사로그 기록
- 연동 결과 및 오류 확인
- 알림 조회 및 읽음 처리

### 로그인 및 접근 권한
- 관리자(ADMIN)와 지도교수(PROF) 역할 구분
- 관리자는 전체 학생 및 관리 기능 접근 가능
- 지도교수는 본인 담당 학생의 명부와 지급 현황 조회
- 관리자 전용 페이지 및 서버 액션 접근 제한
- 서명된 세션 쿠키 기반 로그인 관리

## 4. 로컬 실행 방법

Node.js 및 npm이 설치되어 있어야 합니다.

프로젝트의 `web` 폴더에서 다음 명령어를 실행합니다.

```bash
npm install
```

환경변수는 `.env.example`을 참고하여 개발 환경에 맞게 설정합니다.

주요 환경변수:

- `DATABASE_URL`: 데이터베이스 연결 경로
- `SESSION_SECRET`: 세션 서명용 비밀키
- `CRON_SECRET`: 예약 연동 API 인증키

실제 비밀키 및 데이터베이스 파일은 Git에 업로드하지 않습니다.

개발용 데이터베이스를 준비합니다.

```bash
npm run db:push
npm run db:seed
```

로그인 계정 초기화는 `src/db/seed-auth.ts`를 사용합니다. 실행 전 필요한 지도교수 데이터가 준비되어 있어야 합니다.

개발 서버를 실행합니다.

```bash
npm run dev
```

브라우저에서 http://localhost:3000 에 접속합니다.

Windows PowerShell에서 npm 실행이 제한되는 경우 `npm.cmd` 또는 `npx.cmd`를 사용할 수 있습니다.

## 6. 테스트 및 빌드

### 테스트 환경 자동 설정

GitHub에서 프로젝트를 처음 내려받은 경우에도 별도의 테스트 환경변수 파일을 직접 만들지 않고 테스트를 실행할 수 있다.

테스트에 필요한 설정은 `.env.test.example`에 제공한다.

`npm test`를 실행하면 다음 순서로 진행된다.

1. `scripts/prepare-test.mjs`가 `.env.test` 파일의 존재 여부를 확인한다.
2. 파일이 없으면 `.env.test.example`을 복사해 자동으로 생성한다.
3. 테스트 DB 주소가 정확히 `file:test.db`인지 검사한다.
4. 검사를 통과하면 Drizzle이 테스트 데이터베이스 스키마를 준비한다.
5. Vitest가 전체 자동 테스트를 실행한다.

테스트용 데이터베이스는 로컬 SQLite 파일인 `test.db`를 사용한다.

**주의:** 테스트 실행 시 `test.db`의 구조와 데이터가 변경될 수 있다. 테스트 준비 과정에서 운영용 Turso 데이터베이스를 사용해서는 안 된다.

### 실행 명령어

다음 명령어는 모두 `web/` 폴더에서 실행한다.

TypeScript 검사:

```bash
npx tsc --noEmit
```

전체 자동 테스트:

```bash
npm test
```

프로덕션 빌드:

```bash
npm run build
```

Windows PowerShell에서 npm 실행 정책 오류가 발생하면 `npm.cmd`, `npx.cmd`를 사용할 수 있다.

### 검증 결과

2026년 11월 20일 기준:

- 전체 테스트 파일 **20개 통과**
- 자동 테스트 **90개 통과**
- 테스트 환경변수 파일 자동 생성 검증 성공
- `DATABASE_URL=file:test.db` 안전장치 검증 성공
- TypeScript 검사 통과
- Next.js 프로덕션 빌드 성공

테스트 환경 자동화 기능은 기존 `.env.test`를 임시로 다른 이름으로 변경한 뒤, 새로운 `.env.test`가 자동 생성되는지 확인하고 전체 테스트를 실행하는 방식으로 검증하였다.

`.env`, `.env.local`, `.env.test`, `.env.turso` 등 실제 환경변수 파일은 GitHub에 업로드하지 않는다. 대신 비밀정보가 없는 `.env.example`과 `.env.test.example`만 제공한다.




## 7. 개발 환경 및 보안 주의사항

본 프로젝트는 학습 및 멘토링 목적으로 구현한 웹 기반 업무 시스템이다.

### 운영 환경

- 웹 호스팅: Vercel
- 운영 데이터베이스: Turso
- 서비스 주소: https://stipend-mentoring.vercel.app
- 로컬 개발 데이터베이스: `local.db`
- 자동 테스트 데이터베이스: `test.db`

### 환경변수 및 비밀정보 관리

`.env`, `.env.local`, `.env.test`, `.env.turso` 등의 실제 환경변수 파일은 Git에서 제외한다.

GitHub에는 실제 인증정보가 없는 `.env.example`과 `.env.test.example`만 제공한다.

운영용 데이터베이스 인증 토큰, 세션 비밀키, Cron 인증키는 Vercel 환경변수로 관리한다.

### 운영 데이터 보호

- 개발용 데이터베이스 초기화 명령은 로컬 SQLite에서만 실행하도록 제한한다.
- 운영용 관리자·교수 계정은 별도 생성 도구를 이용한다.
- 운영 계정의 비밀번호는 해싱하여 저장한다.
- 개발용 공통 비밀번호를 운영 계정에 그대로 사용하지 않는다.
- 개발용 Mock 원천 데이터 변경 기능은 운영 환경에서 제한한다.

### 접근 권한 및 자동 연동

관리자와 교수 역할을 구분하고, 교수는 자신이 담당하는 학생의 데이터에만 접근하도록 제한한다.

예약 연동 API `/api/cron/sync`는 `CRON_SECRET`을 사용하는 Bearer 인증으로 보호한다.

Vercel Cron은 매월 5일 UTC 03:00에 실행되도록 등록되어 있다.

### 추가 검증이 필요한 사항

- Cron의 실제 예약 실행 결과 확인
- 새로운 원천 데이터가 들어오는 운영 흐름 검증
- 전체 API에 대한 추가 보안 점검
- 운영 데이터 백업 및 복구 절차 정리
